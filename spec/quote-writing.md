## 1. 목적

사용자가 오늘의 창작 문장을 따라 쓰고,
완료 기록을 돌아보거나 완료 화면을 이미지로 저장하도록 돕는다.

## 2. 이름과 고지

`부처되기`는 제품의 유쾌한 필사 코너 이름이다.
실제 불교 경전이나 부처의 발언을 의미하지 않는다.

| ID | 요구사항 |
| --- | --- |
| QTE-01 | 화면에 `실제 경전 인용이 아닌 화캉스의 창작 문장입니다.`를 표시한다. |
| QTE-02 | 창작 문장을 실제 인물의 직접 인용 형식으로 소개하지 않는다. |
| QTE-03 | 문장 출처를 경전이나 역사적 인물로 허위 표기하지 않는다. |

## 3. 콘텐츠 구성

| ID | 요구사항 |
| --- | --- |
| QTE-04 | 출시 시 중복되지 않는 창작 위로 문장 100개를 제공한다. |
| QTE-05 | 각 문장은 고유 ID를 가진다. |
| QTE-06 | 문장은 공백 포함 15~45자를 권장한다. |
| QTE-07 | 한 문장은 최대 60자를 넘지 않는다. |
| QTE-08 | AI는 초안 생성에 사용할 수 있지만 출시 목록은 사람이 전부 검수한다. |
| QTE-09 | 콘텐츠는 고정 자산으로 제공하며 실행 중 AI를 호출하지 않는다. |

## 4. 콘텐츠 어조

문장은 다음 특성을 지향한다.

- 직장 생활의 흔한 부조리를 가벼운 풍자로 알아주는 말
- `~하는구나`, `~로다`, `~니라`로 끝나는 짐짓 근엄한 가짜 경전체
- 상사, 동료, 회사를 가리키되 실존 인물이 아닌 일반화된 인물상만 등장
- 웃음으로 우회해 위로하는 살짝 능청스러운 유머
- 한 번에 이해되는 짧은 한국어

다음은 포함하지 않는다.

- 공격적인 욕설과 모욕
- 차별과 혐오 표현
- 자해·폭력·범죄 조장
- 특정 개인, 특정 회사, 사용자의 실제 소속을 특정할 수 있는 표현
- 의료·법률·종교적 권위를 가장한 조언
- 실제 불교 교리로 오해할 수 있는 허위 인용
- 사용자의 직장 생활을 위험하게 만들 수 있는 행동 유도

## 5. 문장 예시

- 저들이 다급히 보낸 메일도 자세히 보면 어제 보낼 수 있었던 것이니라.
- 회의가 한 시간을 넘겼으나 결정된 것은 다음 회의 날짜뿐이로다.
- 내게 급한 일이라 하였지만 정작 결재자는 자리를 비웠구나.
- 월급은 한 사람 몫인데 어찌 세 사람의 열정을 바라느냐.
- 상사의 기분은 날씨와 같으니 우산은 쓰되 날씨를 고치려 들지 마라.
- 좋은 의견이라 칭찬받았으나 실행은 내 몫이 되었으니 입을 조심해야겠구나.
- 그대는 오늘도 무례한 말에 예의를 지켰고 급한 일에 숨을 쉬었으니 충분히 장하도다.
- 한낱 미물들이 나를 힘들게 하는구나. 그저 미물이니 내 오늘 참도록 한다.
- 조용히 처리했더니 쉬운 줄 아는구나. 내 유능함이 저이의 눈을 가렸도다.
- 오늘도 별별 자들을 상대했구나. 귀한 내가 넓은 아량으로 또 하루를 살려냈도다.

예시 문장은 콘텐츠 검수 과정에서 같은 기준으로 수정할 수 있다.

## 6. 문장 선택

| ID | 요구사항 |
| --- | --- |
| QTE-10 | 첫 진입 시 아직 보지 않은 문장 중 하나를 무작위로 제시한다. |
| QTE-11 | 한 순환 안에서는 같은 문장을 반복하지 않는다. |
| QTE-12 | 100개를 모두 본 뒤 본 문장 목록을 초기화하고 다시 섞는다. |
| QTE-13 | 현재 문장 ID와 이미 본 문장 ID 목록을 기기에 저장할 수 있다. |
| QTE-14 | 저장값이 손상되면 새 순환을 시작한다. |

권장 선택 방식은 셔플 백이다.

```text
unseen = allMessageIds - seenMessageIds
if unseen is empty:
  seenMessageIds = []
  unseen = allMessageIds
currentMessageId = random(unseen)
```

## 7. 화면 구성

- 상단 헤더: `부처되기`, 오른쪽 ASMR 토글
- 본문 상단: `오늘의 문장`과 따라 쓸 문장
- 본문 중앙: 입력 진행이 반영된 문장 표시
- 본문 하단: 실제 인용이 아니라는 고지
- 입력 영역: 모바일 키보드를 사용하는 텍스트 입력
- 완료 후: 완료 화면, 목록, 다음 필사, 이미지 저장

| ID | 요구사항 |
| --- | --- |
| QTE-15 | 문장은 넉넉한 줄 간격과 여백으로 표시한다. |
| QTE-16 | 화면 진입 즉시 `오늘의 문장`을 보여준다. |
| QTE-17 | 입력란에 진입해도 현재 문장을 함께 볼 수 있다. |
| QTE-18 | 입력한 부분은 진하게, 남은 부분은 옅게 표시한다. |
| QTE-19 | 모바일 키보드가 하단 내비게이션과 입력란을 완전히 가리지 않게 한다. |

## 8. 입력 판정

정규화 규칙:

1. 입력값 앞뒤 공백을 제거한다.
2. 제시 문장 앞뒤 공백을 제거한다.
3. 문장 내부 글자, 공백, 문장부호는 그대로 비교한다.

| ID | 요구사항 |
| --- | --- |
| QTE-20 | 입력이 정답 문장의 접두사와 일치하면 입력한 범위를 완료 색으로 표시한다. |
| QTE-21 | 첫 불일치 지점부터 부드러운 오류 강조를 표시한다. |
| QTE-22 | 불일치가 있어도 입력을 막지 않는다. |
| QTE-23 | 불일치가 있어도 키보드를 닫지 않는다. |
| QTE-24 | 전체 정규화 문자열이 같을 때만 완료 처리한다. |
| QTE-25 | 한글 조합 중간 상태를 오답 완료로 확정하지 않는다. |

## 12. 완료 화면 이미지 저장

이미지 저장 대상은 별도 템플릿이 아니라 현재 보이는 필사 완료 앱 화면이다.
브라우저 주소창, 기기 상태바, 운영체제 UI는 포함하지 않는다.

| ID | 요구사항 |
| --- | --- |
| QTE-48 | `이미지 저장`을 누르면 필사 완료 앱 화면을 현재 스타일 그대로 캡처한다. |
| QTE-49 | 캡처에는 완료 문장, `필사 완료`, 응원 문구, 하단 완료 행동을 포함한다. |
| QTE-50 | 캡처 이미지는 PNG 형식으로 생성한다. |
| QTE-51 | 파일명은 `hwacance-writing-YYYYMMDD.png` 형식을 사용한다. |
| QTE-52 | 이미지 생성은 브라우저 안에서 처리하고 화면이나 문장을 서버로 전송하지 않는다. |
| QTE-53 | 브라우저가 직접 사진 앱 저장을 지원하지 않으면 다운로드 또는 이미지 미리보기를 제공한다. |
| QTE-54 | 캡처 중 버튼 상태 변화나 로딩 표시가 결과 이미지에 들어가지 않게 한다. |
| QTE-55 | 생성이 실패하면 완료 화면을 유지하고 `이미지를 저장하지 못했어요`를 표시한다. |
| QTE-56 | 생성한 이미지 바이너리는 앱 저장소에 영구 보관하지 않는다. |

## 13. 오류와 예외

| 상황 | 동작 |
| --- | --- |
| 문장 목록 로드 실패 | 재시도 행동이 있는 짧은 오류 상태 표시 |
| 문장 목록이 비어 있음 | 기능을 숨기지 않고 콘텐츠 오류 표시 |
| 현재 문장 ID가 없음 | 보지 않은 문장을 다시 선택 |
| 기기 저장 실패 | 현재 세션에서만 셔플 상태 유지 |
| 매우 빠른 연속 다음 탭 | 한 번의 문장 전환만 처리 |
| 붙여넣기 | 일반 입력과 같은 규칙으로 판정 |
| 줄바꿈 입력 | 단일 문장 입력이므로 줄바꿈을 추가하지 않음 |
| 완료 목록 저장 실패 | 현재 세션 목록만 유지하고 필사 완료는 계속 |
| 이미지 캡처 실패 | 완료 화면 유지와 재시도 가능한 오류 표시 |

## 14. 접근성

- 제시 문장과 입력란의 관계를 접근성 설명으로 연결한다.
- 오류 위치를 색상뿐 아니라 상태 문구로 전달한다.
- `필사 완료` 상태를 제목과 안내 문구로 함께 전달한다.
- 입력 진행이 바뀔 때 매 글자마다 스크린 리더 공지를 반복하지 않는다.
- `목록`, `다음 필사`, `이미지 저장`의 이름과 역할을 명확히 구분한다.

## 15. 검수 기준

- [ ] 콘텐츠 목록에 고유 ID를 가진 문장 100개가 있다.
- [ ] 정규화 후 중복 문장이 없다.
- [ ] 모든 문장이 60자 이하다.
- [ ] 금지 표현 기준으로 사람이 전체 목록을 검수했다.
- [ ] 한 순환에서 같은 문장이 반복되지 않는다.
- [ ] 100개 완료 후 새 순환이 시작된다.
- [ ] 일치 입력, 첫 글자 불일치, 중간 불일치가 구분된다.
- [ ] 한글 조합 중 오답 상태가 과도하게 깜빡이지 않는다.
- [ ] 정확한 문장 완성 시 `필사 완료`와 응원 문구가 표시된다.
- [ ] 다음 문장은 다른 미열람 문장을 표시한다.
- [ ] 목록에는 완료한 문장만 최신순으로 한 번씩 표시된다.
- [ ] 좋아요 버튼과 좋아요 상태가 없다.
- [ ] 이미지 저장 시 현재 완료 앱 화면과 같은 PNG가 생성된다.
- [ ] 저장 이미지에 브라우저 주소창과 기기 상태바가 포함되지 않는다.
- [ ] 캡처 실패 후에도 완료 화면과 다음 행동을 사용할 수 있다.
- [ ] 새로고침 후 작성 입력이 남지 않는다.
- [ ] 입력 문자열이 네트워크와 영구 저장소로 전달되지 않는다.
- [ ] 320px 화면과 키보드 열린 상태에서 문장과 입력란을 볼 수 있다.
