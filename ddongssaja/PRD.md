| 문서 종류 | PRD (제품 개요) |
|---|---|
| 최종 갱신 | 2026-08-01 |
| 세부 기능 명세 | [`specs/`](./specs) 폴더의 SPEC 문서 참고 |

이 문서는 **"💩 똥 싸자"** 게임의 제품 개요를 담고 있다. 화면별 세부 동작, 판정 규칙,
수치, 구현 체크리스트 등 기능 단위의 상세 스펙은 이 문서가 아니라 [`specs/`](./specs) 폴더의
개별 SPEC 문서에 정의되어 있다. 이 PRD는 "왜 만드는지, 무엇을 만드는지, 전체 그림이 어떻게
맞물리는지"를 설명하고, 각 기능의 상세는 해당 SPEC으로 안내한다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 게임명 (가칭) | 💩 똥 싸자 |
| 장르 | 캐주얼 아케이드 / 생존형 스코어 게임 |
| 플랫폼 | 모바일 (터치 기반) |
| 핵심 조작 | 드래그(또는 좌우 이동)로 변기를 움직여 떨어지는 똥 받기 |
| 세션 길이 | 짧은 플레이 타임, 반복 플레이 유도 |
| 생명력 | 하트 3개 |
| 난이도 곡선 | 성공 개수 7개 단위 구간마다 상승 |

## 2. 배경 및 문제 정의

이용자가 잠깐 쉬는 시간(화장실, 대기 줄, 이동 중 등)에 아주 짧게 즐길 수 있는
가벼운 캐주얼 게임이 필요하다. 복잡한 튜토리얼이나 학습 곡선 없이, 화면을 본 순간
바로 이해되는 단순한 규칙과 즉각적인 성취감(칭찬 피드백, 점수 상승)을 주는 것이
이 게임의 핵심 문제 정의다.

- 규칙이 복잡하면 "짧게 반복 플레이"라는 목적과 충돌한다.
- 아무 긴장감이 없으면 몇 번 하다 흥미를 잃는다 → 난이도 상승과 생명력 시스템으로 긴장감 부여.
- 성공했을 때 아무 반응이 없으면 손맛이 없다 → 성공 시 칭찬 피드백 문구로 보완.

## 3. 목표 및 성공 기준

- **이해 용이성**: 첫 플레이에서 설명 없이도 조작법을 파악할 수 있어야 한다.
- **반복 플레이 유도**: "내 최고 기록을 넘고 싶다"는 동기를 계속 만들어내야 한다.
- **적정 긴장감**: 하트 3개 덕분에 한 번의 실수로 바로 끝나지 않되, 난이도 상승으로
  결국에는 누구나 게임이 끝나는 구조여야 한다.
- **가벼운 만족감**: 성공할 때마다 짧은 칭찬 문구로 소소한 재미를 준다.

이 지표들은 정성적 목표이며, 정량적 성공 기준(재방문율, 평균 세션 길이 등)은 아직
수립되지 않았다 — [11. 향후 논의가 필요한 사항](#11-향후-논의가-필요한-사항-open-questions) 참고.

## 4. 타겟 사용자

- 짧은 자투리 시간에 부담 없이 즐길 캐주얼 게임을 찾는 모바일 이용자
- 복잡한 룰이나 긴 튜토리얼을 원하지 않는 라이트 유저
- 최고 기록 경신, 반복 도전형 게임을 좋아하는 유저

## 5. 게임 목적 (한 줄 피치)

떨어지는 똥을 변기에 넣어 점수를 획득하는 단순하고 직관적인 캐주얼 게임을 제공한다.
성공 개수에 따라 점점 빨라지는 난이도와, 휴지라는 방해 요소를 통해 짧은 시간 안에
순간적인 판단력과 집중력을 요구하는 재미를 준다. 성공할 때마다 뜨는 짧은 칭찬 문구는
플레이의 손맛을 더한다.

## 6. 화면 흐름

```
[시작 화면]
   |  "똥 싸기 시작" 버튼 탭
   v
[플레이 화면] --- 하트 3개 모두 소진 ---> [결과 화면]
   ^                                          |
   |                 "다시 시작" 등 재도전 경로 |
   +------------------------------------------+
```

- **시작 화면**: "똥 싸기 시작" 버튼만 있는 단순한 진입 화면. 팝업(모달) 카드 형태로 표시된다.
  상세: [SPEC 01](./specs/01-core-gameplay.md), 비주얼: [design.md 8장](./design.md#8-팝업모달-컴포넌트)
- **플레이 화면**: 변기 조작, 낙하물 받기, 난이도 상승, 생명력 감소, 성공 피드백 문구가
  모두 이 화면에서 일어난다. 화면 좌상단에는 브랜드 로고가 항상 표시된다
  ([design.md 7장](./design.md#7-로고-브랜드-워드마크)).
- **결과 화면**: 총 성공 개수와 마무리 메시지를 보여준다. 시작 화면과 동일한 팝업 카드
  형태로 표시된다. 상세: [SPEC 05](./specs/05-result-screen.md)

## 7. 핵심 시스템 요약

아래는 각 시스템의 한눈에 보기 요약이다. 판정 규칙, 수치, 구현 체크리스트 등
세부 사항은 각 SPEC 문서를 참고한다.

### 7.1 코어 플레이 — [SPEC 01](./specs/01-core-gameplay.md)

- 화면 하단 중앙의 변기를 좌우로 움직여 위에서 떨어지는 똥을 받는다.
- 똥을 받으면 점수 +1, 놓치면 생명력 -1.
- 낙하물에는 똥과 휴지 두 종류가 섞여 떨어진다.

### 7.2 난이도 상승 — [SPEC 02](./specs/02-difficulty-progression.md)

- 성공 개수가 **7개 단위**로 쌓일 때마다 난이도 구간이 오른다.
- 구간이 오르면 낙하 속도와 휴지 등장 비중이 함께 상승한다.

### 7.3 생명력 시스템 — [SPEC 03](./specs/03-life-system.md)

- 화면 우측 상단에 하트 3개로 생명력을 표시한다.
- 휴지를 받거나 똥을 놓치면 하트가 하나씩 빈 하트로 바뀐다.
- 하트가 모두 소진되면 게임이 종료된다.

### 7.4 성공 피드백 문구 — [SPEC 04](./specs/04-feedback-messages.md)

- 똥을 변기에 넣을 때마다 변기 옆에 짧은 칭찬 문구가 잠깐 노출된다.
- "넌 참 잘했어.", "명중!", "역시 프로야." 등 10개 문구 중 무작위로 선택되어 표시된다.

### 7.5 결과 화면 — [SPEC 05](./specs/05-result-screen.md)

- 게임 종료 시 총 성공 개수("총 37개의 똥을 변기에 넣었습니다!")와 마무리 메시지
  ("오늘도 고생했어요. 🚽✨")를 보여준다.

## 8. 참고 비주얼 자산

`ddongssaja/` 폴더에는 기획 문서 외에 참고용 이미지 자산(워드마크, 똥/휴지 참고 이미지 등)이
함께 보관되어 있을 수 있다. 이 자산들은 비주얼 톤을 참고하기 위한 것이며, 최종 게임 내
그래픽 사양(해상도, 애니메이션 프레임 등)을 정의하지는 않는다. 실제 그래픽 사양은
구현 단계에서 별도로 정리한다.

## 9. 개발 범위 (MVP)

**포함 (In scope)**

- 시작 화면 + "똥 싸기 시작" 버튼 (팝업 카드 형태)
- 변기 좌우 조작, 똥/휴지 낙하 및 판정
- 7개 단위 난이도 상승 (속도 + 휴지 비중)
- 하트 3개 생명력 시스템
- 성공 시 칭찬 피드백 문구
- 결과 화면 (총 성공 개수 + 마무리 메시지, 팝업 카드 형태)
- 좌상단 브랜드 로고 상시 노출

**제외 (Out of scope, 이번 범위 아님)**

- 인앱결제, 광고, 소셜 공유
- 서버 연동 랭킹/리더보드 (로컬 최고 기록 여부는 Open Question)
- 아이템/파워업 시스템
- 사운드/이펙트 디자인 (필요 시 별도 SPEC으로 추후 정의)

## 10. 성공 여부 검증 방법

- 내부 플레이테스트에서 "규칙을 설명 없이 이해했는가"를 확인한다.
- 동일 이용자가 여러 판을 연속으로 플레이하는지(반복 플레이 의향) 관찰한다.
- 난이도 구간 상승이 "적당히 어려워진다"고 느껴지는지, 너무 급격하거나 밋밋하지 않은지
  플레이테스트로 확인하고 [SPEC 02](./specs/02-difficulty-progression.md)의 수치를 조정한다.

## 11. 향후 논의가 필요한 사항 (Open Questions)

아래는 아직 확정되지 않은 사항의 모음이다. 각 항목의 배경은 해당 SPEC 문서에도
동일하게 기록되어 있다.

- 변기 이동 조작 방식: 드래그 vs 좌우 버튼 vs 기울기(자이로) 등 확정 필요 ([SPEC 01](./specs/01-core-gameplay.md))
- 낙하물-변기 충돌 판정 영역(히트박스) 크기 ([SPEC 01](./specs/01-core-gameplay.md))
- 난이도 곡선 구체적 수치: 7개 단위 구간별 속도 증가율(%) 및 휴지 등장 확률,
  그리고 각각의 상한값 ([SPEC 02](./specs/02-difficulty-progression.md))
- 하트 회복 여부: 플레이 도중 하트가 다시 채워지는 요소(아이템 등)가 있는지 ([SPEC 03](./specs/03-life-system.md))
- 성공 피드백 문구의 정확한 노출/페이드아웃 시간, 폰트/색상 등 비주얼 스타일,
  향후 문구 세트 확장 여부 ([SPEC 04](./specs/04-feedback-messages.md))
- 최고 기록 저장 방식: 로컬 저장 vs 서버/랭킹 연동 여부 ([SPEC 05](./specs/05-result-screen.md))
- 결과 화면의 "다시 시작" 버튼 동작 방식 ([SPEC 05](./specs/05-result-screen.md))
- 사운드/이펙트, 추가 아이템(예: 점수 2배 등) 도입 여부

## 13. 변경 이력

- **v1**: 기본 코어 루프(변기, 똥 낙하, 점수, 시간 기반 난이도 상승, 휴지 방해 요소) 정의
- **v2**: 시작 화면 버튼, 하트 3개 생명력 시스템, 성공 개수 10개 단위 난이도 상승으로 개정
- **v3**: 단일 PRD를 개요 문서로 재구성하고 기능별 SPEC 문서로 분리, 성공 시 칭찬
  피드백 문구 시스템 추가
- **v4**: 시작/결과 화면을 팝업(모달) 카드 형태로 변경, 버튼 크기 축소, 좌상단 브랜드
  로고 상시 노출 추가, 난이도 상승 단위를 10개에서 7개로 변경(플레이 한 판이 너무
  길다는 피드백 반영)

## 14. 용어 정리 (Glossary)

| 용어 | 정의 |
|---|---|
| 변기 | 이용자가 좌우로 조작하는 플레이어 오브젝트. 화면 하단 중앙에 위치 |
| 똥 | 득점 대상 낙하물. 변기에 들어가면 점수 +1 |
| 휴지 | 방해 요소 낙하물. 득점 대상 아님. 변기에 들어가면 생명력 -1 |
| 성공 개수 | 똥을 변기에 넣어 획득한 누적 점수. 난이도 구간 계산의 기준 |
| 구간 (난이도 구간) | 성공 개수 7개 단위로 구분되는 난이도 단계. 구간마다 속도·휴지 비중 상승 |
| 생명력 (하트) | 화면 우측 상단에 표시되는 3개의 하트. 0이 되면 게임 종료 |
| 피드백 문구 | 똥을 성공적으로 받을 때 변기 옆에 짧게 뜨는 칭찬 문구 |
| 결과 화면 | 게임 종료 후 총 성공 개수와 마무리 메시지를 보여주는 화면 |
| 팝업(모달) | 시작/결과 화면에서 콘텐츠를 담는 사각형 카드. 배경 스크림 위에 떠 있는 형태 |
| 로고 | 화면 좌상단에 상시 노출되는 `똥 싸자.png` 브랜드 워드마크 |
