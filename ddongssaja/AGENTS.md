# AGENTS.md

이 문서는 `ddongssaja` (💩 똥 싸자) 프로젝트에서 작업하는 AI 코딩 에이전트를 위한 가이드입니다.
문서 구조가 두 층으로 나뉘어 있습니다.

- **[PRD.md](./PRD.md)**: 제품 개요("왜/무엇을 만드는지"). 세부 규칙은 여기 없습니다.
- **[`specs/`](./specs)**: 기능별 상세 명세("어떻게 동작해야 하는지" + 구현 체크리스트).
  - [01-core-gameplay.md](./specs/01-core-gameplay.md) — 시작 화면, 변기 조작, 낙하물 판정
  - [02-difficulty-progression.md](./specs/02-difficulty-progression.md) — 7개 단위 난이도 상승
  - [03-life-system.md](./specs/03-life-system.md) — 하트 3개 생명력 시스템
  - [04-feedback-messages.md](./specs/04-feedback-messages.md) — 성공 시 칭찬 피드백 문구
  - [05-result-screen.md](./specs/05-result-screen.md) — 결과 화면
- **[design.md](./design.md)**: 색상, 타이포그래피, 배경 패턴, 버튼 컴포넌트, 이미지 에셋 매핑
  등 "어떻게 보여야 하는지"(시각 표현). 기능 동작이 아닌 스타일/에셋 작업 시 여기를 따릅니다.

규칙을 확인하거나 구현할 때는 기능 동작은 **해당 SPEC 문서**, 색상/폰트/버튼 등 스타일은
**design.md**를 먼저 읽습니다. PRD는 전체 그림과 Open Questions 목록을 확인할 때 참고합니다.

## 프로젝트 개요

- 캐주얼 아케이드 생존형 스코어 게임
- "똥 싸기 시작" 버튼으로 시작하는 단일 코어 루프: 변기를 좌우로 움직여 떨어지는 똥을 받음
- 시작/결과 화면은 팝업(모달) 카드 형태로 표시됨 (design.md 8장)
- 성공 개수 7개 단위 구간마다 낙하 속도와 휴지 비중이 함께 증가하는 난이도 곡선
- 똥과 섞여 떨어지는 "휴지"는 방해 요소(득점 대상 아님)
- 하트 3개의 생명력 시스템: 휴지를 받거나 똥을 놓치면 하트 1개 감소, 0개가 되면 종료
- 똥을 성공적으로 받을 때마다 변기 옆에 짧은 칭찬 피드백 문구가 노출됨
- 화면 좌상단에 "똥 싸자" 브랜드 로고가 상시 노출됨 (design.md 7장)

## 작업 원칙

1. **SPEC을 진실의 원천으로 삼기**: 기능 규칙(득점 조건, 종료 조건, 난이도 상승, 문구 목록 등)을
   변경하거나 확장할 때는 해당 `specs/*.md`를 먼저 갱신한 뒤 구현에 반영합니다. 규칙이 여러
   시스템에 걸쳐 있다면(예: 난이도 상승이 생명력에 영향을 주는지) 관련된 모든 SPEC 문서를
   함께 갱신합니다. 규칙이 PRD의 요약(7장)에도 영향을 주면 `PRD.md`도 함께 갱신합니다.
2. **Open Questions 우선 확인**: 각 SPEC 문서 하단과 `PRD.md`의 "향후 논의가 필요한 사항"에
   미확정 항목이 정리되어 있습니다(조작 방식, 난이도 곡선 구체 수치, 하트 회복 여부, 피드백
   문구 노출 시간, 최고 기록 저장 방식 등). 관련 기능을 구현하기 전에는 사용자에게 확인하거나,
   합리적인 기본값을 가정한 뒤 해당 SPEC 문서에 그 결정을 기록합니다.
3. **최소 범위 구현**: 짧은 세션/단순 조작이라는 게임의 정체성에 맞게, 요청받지 않은 부가 기능
   (예: 인앱결제, 소셜 공유, 복잡한 아이템 시스템)을 임의로 추가하지 않습니다.
4. **작은 단위로 검증 가능하게**: 핵심 루프(낙하 → 드래그 → 판정 → 점수, [SPEC 01](./specs/01-core-gameplay.md))를
   먼저 동작하게 만들고, 난이도 곡선([SPEC 02](./specs/02-difficulty-progression.md)),
   생명력([SPEC 03](./specs/03-life-system.md)), 피드백 문구([SPEC 04](./specs/04-feedback-messages.md))는
   그 위에 순서대로 추가합니다.

## 핵심 게임 로직 체크리스트

새로운 구현이나 변경 사항이 아래 규칙을 만족하는지 확인합니다. 각 항목의 상세 근거는
괄호 안 SPEC 문서를 참고하세요.

- [ ] 시작 화면에 "똥 싸기 시작" 버튼이 있으며, 눌러야 게임 플레이가 시작된다. ([SPEC 01](./specs/01-core-gameplay.md))
- [ ] 시작 화면과 결과 화면은 팝업(모달) 카드 안에 모든 내용을 담아 표시하고, 뒤 배경은
      어둡게 가리지 않고 흰 그리드 배경을 그대로 유지한다. (design.md 8장)
- [ ] 결과 화면의 총 성공 개수 문구는 자릿수와 무관하게 항상 한 줄로 표시된다. (design.md DSN-24)
- [ ] 화면 좌상단에 "똥 싸자" 로고가 모든 화면에서 항상 보인다. (design.md 7장)
- [ ] 변기는 화면 하단 중앙에 위치하고 좌우로만 이동한다. ([SPEC 01](./specs/01-core-gameplay.md))
- [ ] 똥은 화면 상단에서 지속적으로 생성되어 아래로 떨어진다. ([SPEC 01](./specs/01-core-gameplay.md))
- [ ] 똥이 변기 영역에 도달하면 점수가 1 증가하고, 변기 옆에 칭찬 피드백 문구가 노출된다.
      ([SPEC 01](./specs/01-core-gameplay.md), [SPEC 04](./specs/04-feedback-messages.md))
- [ ] 칭찬 피드백 문구는 지정된 10개 문구 목록 중 무작위로 선택되며, 짧게 노출 후 사라진다.
      ([SPEC 04](./specs/04-feedback-messages.md))
- [ ] 성공 개수가 7개 단위로 누적될 때마다 낙하 속도와 휴지 등장 비중이 함께 증가한다.
      ([SPEC 02](./specs/02-difficulty-progression.md))
- [ ] 휴지는 똥과 함께 랜덤하게 섞여 떨어지며, 변기에 들어가도 점수에 영향이 없다. ([SPEC 01](./specs/01-core-gameplay.md))
- [ ] 우측 상단에 하트 3개(생명력)를 표시한다. ([SPEC 03](./specs/03-life-system.md))
- [ ] 휴지를 변기에 넣거나 똥을 놓치면(변기를 지나쳐 화면 밖으로 나가면) 하트가 1개 감소한다.
      ([SPEC 03](./specs/03-life-system.md))
- [ ] 하트가 0개가 되면 게임이 종료된다. (하트가 남아있는 동안은 실수해도 게임이 계속된다) ([SPEC 03](./specs/03-life-system.md))
- [ ] 종료 시 결과 화면에 총 성공 개수와 마무리 메시지를 표시한다. ([SPEC 05](./specs/05-result-screen.md))
- [ ] 최고 기록(하이스코어)을 확인하고 갱신할 수 있는 장치를 제공한다. ([SPEC 05](./specs/05-result-screen.md))

## 커밋/PR 가이드

- 변경 사항이 게임 규칙(SPEC/PRD 내용)에 영향을 준다면 커밋 메시지나 PR 설명에 어떤 규칙이
  왜 바뀌었는지, 어떤 SPEC 문서를 함께 갱신했는지 명시합니다.
- 에셋(이미지 등)을 추가/교체할 때는 파일명과 용도를 README.md의 폴더 구성과 design.md의
  "이미지 에셋" 표에 반영합니다.
- 새 기능 영역이 기존 5개 SPEC 어디에도 속하지 않는다면, 임의로 기존 문서에 욱여넣지 말고
  `specs/06-...` 형식으로 새 SPEC 파일을 만들고 PRD.md의 문서 구성 안내(12장)에 추가합니다.
